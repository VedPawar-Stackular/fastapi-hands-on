Docker + Postgres — Setup Cheatsheet

ticket-tracker project (FastAPI + SQLModel + asyncpg) — quick reference for both flows

Case 1

Resume work — same database, after reboot/laptop close

1. Start Docker Desktop

Launch it, wait for the whale icon to say "running." If daemon isn't up yet, every docker command fails with a pipe/socket error.

2. Start the Postgres container

docker ps -a

Find your container (e.g. ticket-db or renamed local-postgres). Then:

docker start ticket-db

3. Verify it's actually listening

docker ps --filter "name=ticket-db" --format "table {{.Names}}\t{{.Status}}\t{{.Ports}}"

Confirm PORTS shows 0.0.0.0:5432->5432/tcp.

Watch out: if you have multiple Postgres containers mapped to the same host port 5432, only start the one you need — two containers can't bind the same host port at once.

4. Start the API

uv run uvicorn app:app --reload

Swagger UI: http://127.0.0.1:8000/docs

5. DBeaver / VS Code PostgreSQL Explorer

Just reopen — existing connection reconnects automatically once the container is up. Nothing to reconfigure.

Case 2

New database connection — for a new project

Key idea

One Postgres container (server) can hold many databases. You don't need a new container per project — just a new database name inside the existing one, unless you want full isolation (own data volume, own lifecycle).

Option A — new database inside the existing container (simplest)

docker exec -it ticket-db psql -U ticketuser -d ticketdb -c "CREATE DATABASE newprojectdb;"

New project's .env:

DATABASE_URL=postgresql+asyncpg://ticketuser:ticketpass@localhost:5432/newprojectdb

Option B — brand new container (full isolation, own volume)

docker run --name newproject-db `
  -e POSTGRES_USER=newuser `
  -e POSTGRES_PASSWORD=newpass `
  -e POSTGRES_DB=newdb `
  -p 5433:5432 `
  -v newproject-db-data:/var/lib/postgresql/data `
  -d postgres:16

Note the different host port (5433) to avoid clashing with the existing container on 5432. .env:

DATABASE_URL=postgresql+asyncpg://newuser:newpass@localhost:5433/newdb

The -v flag is a named volume — without it, deleting the container wipes all data.

Connecting it in VS Code (ckolkman.vscode-postgres extension)

"Add Connection" asks 7 questions in order:

#PromptWhat to enter
1Hostnamelocalhost
2User to authenticate ase.g. ticketuser
3Passworde.g. ticketpass
4Port number5432 (or 5433 for Option B)
5Database name (blank = show all)leave blank — lists every database on that server under one tree
6Connection typeStandard connection (no SSL for local docker)
7Display nameanything readable, e.g. local-postgres
Before adding a new connection: expand your existing localhost entry first and refresh it. If step 5 was left blank when it was created, the new database will just appear there automatically — no second connection entry needed at all.
